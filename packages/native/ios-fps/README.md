# Physical iOS performance helper

A standalone macOS arm64 helper using idevice's paired-device CoreDeviceProxy userspace tunnel for Instruments graphics DTX and the device debugproxy. Requires physical iOS 17.4+ devices with Developer Mode enabled. No root, app SDK, Python runtime or Instruments GUI is needed. Display FPS does not attach a debugger; CPU and memory attach to an already running app.

`mobile-dev-ios-fps fps <UDID>` reads the global `CoreAnimationFramesPerSecond` counter at a one-second sampling interval. It reports the immediate baseline measurement as its `ready` record instead of a reading and never substitutes a missing counter with zero. Idle displays can report zero; this measures display updates rather than panel refresh rate, and does not attribute a change to an app.

`mobile-dev-ios-fps debugserver <UDID>` opens the device debugproxy through the same paired-device tunnel. It publishes a loopback TCP port in its `ready` record and forwards the GDB protocol until the client disconnects or the helper is asked to stop. The existing CPU collector negotiates detach-on-error before attaching by PID, streams thread CPU counters and physical memory footprint, and detaches without terminating the app. This mode requires a development-signed app with `get-task-allow`, a mounted developer disk image, and no existing debugger attachment. Attach and detach briefly pause the app; neither launches or restarts it.

Both modes follow the shared native-helper protocol: stdout carries one JSON record per line, the first is `{"type":"ready"}` (debugserver adds its `port`), and a handled failure ends with `{"type":"error","cause":"<snake_case>","message":"<text>"}` and a non-zero exit. The causes are `invalid_arguments`, `device_not_found`, `connection_timeout`, `connection_failed`, `service_open_timeout`, `service_open_failed`, `sampling_failed`, `sample_timeout`, `sample_failed`, `invalid_sample`, `listen_failed`, `forward_failed`, `output_failed` and `internal`. EOF on stdin or SIGTERM stops the helper with exit status 0, which also closes the developer connection; so does a closed stdout.

`mobile-dev-ios-fps foreground <UDID>` queries the paired accessibility audit service for the current screen element and emits one JSON line containing its owning `pid`, or `null` when no element is available. The 20-byte physical-device token starts with a little-endian process ID. The server matches it only against eligible development apps' main processes. The query leaves inspector visuals hidden and event monitoring neutral, without moving focus or interacting with the screen. Inspector and app monitoring state are cleaned up after success, failure, timeout or SIGTERM. Connection failures and unsupported token formats report an error; they never select a guessed app.

Build using `npm run rebuild:ios-fps`. The shared `packages/native/Cargo.lock` and the idevice Git revision pin dependencies; the build records source and binary SHA-256 hashes and dependency licenses in vendor/ios-fps.
